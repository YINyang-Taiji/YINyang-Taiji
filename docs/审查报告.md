# AI 个人档案 —— 需求审查与完善方案报告

> 本文档是需求审查的完整结论：发现的问题、完善方案、以及已落地的设计产出。
> 面向原始需求：记录习惯/语气/思维/作息/软件/AI平台作品/偏好/对AI要求/功能设置/行为地点时间轴，支持跨机、跨平台复用，手动/自动周期更新，ZIP+.md，Windows/Linux，本地或自定义云端。

---

## 一、总评

你的**立意很好**，但原始方案是"**能打包的档案**"，不是"**能复用的身份**"。真正的分水岭在于三件事：① 用结构化 Schema 而非纯 Markdown 承载机器数据；② 建平台适配器 + 能力协商；③ 做好加密、版本合并与导入回滚。补上这三件事，工具就从"数据收集器"升级为"真正即插即用的 AI 个人身份卡"。

---

## 二、发现的漏洞与完善方案

| # | 漏洞 | 完善方案 | 状态 |
|---|---|---|---|
| 1 | **隐私安全空白**：ZIP 非加密，行为地点/时间轴/作息最敏感 | 默认 AES-256-GCM 加密；分层敏感度 public/private/secret；local-first；脱敏匿名ID；最小化收集 | ✅ 已设计 |
| 2 | **跨 AI 平台不成立**："任何一个平台都能用"是理想化，各平台上下文/角色/能力不同 | 定义标准 Schema + 平台适配器层 + 能力协商；改写为"实现标准适配器接口的平台" | ✅ 已设计 |
| 3 | **自动更新无触发源、防污染缺失** | 三类触发（时间/事件/手动）+ 置信度门 + 暂存区 + 人在回路；负向偏好/红线防污染 | ✅ 已设计 |
| 4 | **多设备合并/冲突未设计**（会互相覆盖） | base 三方字段级合并 + 冲突仲裁（置信度/时间戳/来源）+ 冲突写文件不静默覆盖 | ✅ 已设计 |
| 5 | **ZIP+.md 结构脆弱**：机器逻辑建在 Markdown 上 | 混合双视图：机器走 JSON+Schema 校验，.md 仅人读摘要 | ✅ 已落地 |
| 6 | **命名碰撞与合规风险**（非法字符/同名/PII） | 消毒 + UTC + 主机哈希 + 匿名ID 可选项 | ✅ 已设计 |
| 7 | **缺导入/迁移/回滚链路** | 导入校验管线（checksum→Schema→冲突→dry-run→确认→快照→生效）+ 回滚 + self-test | ✅ 已设计 |
| 8 | **缺负向偏好/红线/边界**（AI 只顺习惯不避红线） | negative_preferences + guardrails(hard/soft) + exceptions + edge_cases | ✅ 已纳入 Schema |
